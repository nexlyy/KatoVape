# Резервные копии

Бэкап, который ни разу не разворачивали, бэкапом не считается. Поэтому здесь два раздела:
как снять копию и как проверить, что из неё действительно поднимается магазин.

## Что уже есть на стороне Supabase

Смотреть в панели проекта: **Database → Backups**.

Что там может быть:

- список ежедневных копий с датами. Значит, автоматические бэкапы включены, и в худшем
  случае вы теряете день работы;
- предложение перейти на платный тариф. Значит, автоматических копий нет вовсе, и
  единственная копия базы это та, которую вы снимете сами;
- отдельная вкладка **Point in time recovery**. Это откат на произвольную минуту, а не на
  вчерашнюю ночь. Стоит денег и включается отдельно от обычных бэкапов.

Разница на практике простая. Без PITR восстановление вернёт вас к последней ночи: заказы,
принятые за день, придётся собирать из переписки с менеджерами. С PITR можно откатиться на
минуту до неудачного запроса.

Магазин продаёт каждый день, база небольшая, поэтому разумный минимум это ежедневные копии
плюс своя выгрузка перед каждым опасным действием: миграцией, чисткой, массовой правкой цен.

## Своя копия

Проект слинкован с CLI, поэтому команды короткие. Из корня репозитория:

```bash
supabase db dump --linked -f backup-schema.sql
```

Это схема: таблицы, функции, политики, триггеры. Данных в ней нет.

```bash
supabase db dump --linked --data-only -f backup-data.sql
```

А это данные: ассортимент, заказы, клиенты, партии, журналы.

Два файла рядом это полная копия. Держите их вне рабочего компьютера: облако, второй диск,
что угодно, кроме той же машины. И не кладите в репозиторий, там телефоны и адреса клиентов.

Перед чисткой или миграцией достаточно выгрузки данных: схема лежит в `supabase/migrations`
и восстанавливается из них.

## Репетиция восстановления

Смысл репетиции в том, чтобы узнать про сломанный бэкап заранее, а не в тот вечер, когда он
понадобился. Разворачиваем не в боевой проект, а в отдельный.

1. Завести второй проект Supabase, бесплатного тарифа хватит. Назвать понятно, например
   `katovape-restore-test`.

2. Взять строку подключения: **Project Settings → Database → Connection string → URI**.
   Пароль там подставляется тот, что вы задали при создании проекта.

3. Накатить схему:

   ```bash
   supabase db push --db-url "postgresql://postgres:ПАРОЛЬ@db.ЧТО-ТО.supabase.co:5432/postgres"
   ```

4. Залить данные:

   ```bash
   psql "postgresql://postgres:ПАРОЛЬ@db.ЧТО-ТО.supabase.co:5432/postgres" -f backup-data.sql
   ```

   `psql` не входит в CLI, это клиент Postgres. На Windows ставится одной командой:
   `scoop install postgresql`.

5. Проверить, что приехало. В SQL-редакторе тестового проекта:

   ```sql
   select 'orders'  as t, count(*) from public.orders
   union all select 'products',    count(*) from public.products
   union all select 'profiles',    count(*) from public.profiles
   union all select 'stock_moves', count(*) from public.stock_moves;
   ```

   Числа должны сойтись с боевой базой. Если где-то ноль, копия неполная, и лучше выяснить
   это сейчас.

6. Удалить тестовый проект. Он содержит настоящие телефоны и адреса, и жить ему незачем.

Полчаса раз в пару месяцев. Если после обновления CLI или смены схемы что-то перестанет
разворачиваться, вы узнаете об этом на репетиции.

## Что копия не вернёт

Дамп это только база. Отдельно живут:

- **Edge Functions** — лежат в `supabase/functions`, деплоятся заново командой
  `supabase functions deploy`;
- **секреты** — токен бота, ключи Stripe. Их в дампе нет и быть не должно; храните отдельно
  в менеджере паролей;
- **бот на VPS** — это `server/`, поднимается из репозитория по `deploy/DEPLOY.md`;
- **фото товаров** — `data/photos`, они в репозитории.

То есть при полной потере проекта Supabase порядок такой: новый проект, `supabase db push`,
заливка данных, деплой функций, проставить секреты, поменять URL и ключ в `shared/config.js`
и в `.env` бота.

## Когда снимать копию обязательно

- перед `supabase db push` с новой миграцией;
- перед чисткой базы (`supabase/maintenance/reset-test-data.sql`);
- перед массовой правкой цен или остатков;
- перед включением оплаты картой.
